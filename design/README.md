# UI/UX design - how the Figma file is produced

The Figma file for this project is generated by a Figma plugin rather than drawn by hand.
The plugin source is in [`figma-plugin/`](figma-plugin/).

## Why a plugin

Figma has no API for creating design content — the REST API is read-only for file contents,
so a design cannot be produced from outside the editor. The Plugin API *can* create frames,
components, text and prototype links. Generating the file this way has three advantages
over drawing 23 frames by hand:

1. **Consistency is guaranteed.** Every screen is assembled from the same nine components
   and the same spacing constants, so the visual hierarchy cannot drift between screens.
2. **It is reproducible.** If a requirement changes, the change is made once in `code.js`
   and the file is regenerated — which matters for the Week 7 demonstration, where a change
   must propagate consistently across artefacts.
3. **It is reviewable.** The design is version-controlled as source, so the commit history
   shows how the design evolved.

The generated file is a normal Figma file: real layers, real components, real prototype
links. It can be edited by hand afterwards like any other.

## What it generates

| Page | Contents |
|---|---|
| `01 - Design System` | Colour scale, type scale, and 9 reusable components: 3 button variants, 2 field states, 3 status badges, 1 event card |
| `02 - Wireframes (lo-fi)` | 6 greyscale wireframes — the design-phase artefact showing layout and navigation flow before any visual styling |
| `03 - Hi-fi Screens` | 17 screens covering both roles and all four required states, with 8 prototype links wired |

**23 frames total.**

### State coverage (required by the brief)

| State | Where it appears |
|---|---|
| Normal | `R9 - Event Listing`, `R6 - Organiser Dashboard`, `R12 - My Bookings`, `R5 - Create Event` |
| Empty | `R9 - Event Listing (empty state)`, `R6 - Organiser Dashboard (empty)`, `R12 - My Bookings (empty)` |
| Validation / error | `R1 - Register (validation errors)`, `R2 - Login (error)`, `R5 - Create Event (validation errors)`, `R11 - Sold Out / Capacity Conflict` |
| Success | `R10 - Booking Success` |

### Prototype flows

**W1 — publish and book (attendee path):**
`R2 - Login` → `R9 - Event Listing` → `R10 - Book Tickets` → `R10 - Booking Success` → `R12 - My Bookings`

**W1 — organiser path:**
`R1 - Register` → `R6 - Organiser Dashboard` → `R5 - Create Event` → back to dashboard

**W2 — cancel and release:**
`R12 - My Bookings` → `R13 - Cancel Booking Confirm`

Frame names are prefixed with the requirement ID so the traceability matrix in
[`../docs/06-system-design.md`](../docs/06-system-design.md) points directly at them.

## How to run it

Local plugin development requires the **Figma desktop app** — the browser version cannot
import a plugin from a local folder.

1. Install the Figma desktop app from figma.com/downloads and sign in.
2. Create a new design file, name it **Event Ticket Booking System**.
3. Menu (top-left) → **Plugins** → **Development** → **Import plugin from manifest…**
4. Select `design/figma-plugin/manifest.json` from this repository.
5. Menu → **Plugins** → **Development** → **Event Ticket Booking - Design Generator**.

It runs in a few seconds and leaves you on page `03 - Hi-fi Screens`.

### Then, to get the view-only link required for submission

1. **Share** (top right) → set link access to **Anyone with the link** → **can view**.
2. Copy the link and record it in [`../docs/00-submission-links.md`](../docs/00-submission-links.md).

To demonstrate the prototype rather than the canvas, select the `R2 - Login` frame and use
Present; share that URL instead if a clickable prototype link is wanted.

## Verifying it before running

`test-harness.js` executes `code.js` against an offline stub of the Plugin API to catch
runtime errors without opening Figma:

```
node test-harness.js
```

Expected output: 3 pages, 23 frames, 9 components, 8 prototype links, `ALL CHECKS PASSED`.
The harness is a development aid and is not part of the plugin itself.

## Known limitations

- Frames use fixed positioning rather than auto-layout. Auto-layout would be more faithful
  to production Figma practice, but fixed positioning is deterministic and keeps the
  generator readable. Resizing a frame by hand will not reflow its contents.
- The prototype links are single-step `ON_CLICK` navigations on whole frames, not on
  individual buttons. This is enough to walk both workflows, but a hand-authored prototype
  would attach the trigger to the specific button.
- Colour and type styles are drawn from constants in `code.js` but are not published as
  Figma *styles*, so they do not appear in the file's style library.
